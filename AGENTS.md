# Agent taste vault

The user's taste and knowledge, kept as a small wiki so Claude Code can apply and look them up. The agent writes rules in session when the user corrects it or a failure or dated source shows what works, and the hooks in `tools/hooks/` deliver them back to the agent from then on. Pages hold knowledge in the agent's words, and sessions read them through `index.md`. The user reads, edits and deletes the notes in Obsidian.

## Layout

- `raw/` holds sources and is append-only.
  - `raw/inbox/<date>.jsonl`: rules the agent proposed in session (`source: agent`, `a-` ids), written by `tools/propose.mjs`. Older rows, with `c-` and `p-` ids, are preferences captured from sessions before proposals existed.
  - `raw/picks/<date>.jsonl`: the user's picks between options and their comments on one piece of work, word for word, with `q-` ids, written by `tools/pick.mjs` (see Picks). Rows with no `subject` are questions captured alongside those older inbox rows. The sheet a pick was made from sits beside them as `<date>-<subject>.<ext>`.
  - `raw/refs/`: references the user collects. You may add new files here.
- `wiki/<domain>/<slug>.md`: one rule per note, or a page (see Pages). Domains and their project folders are in `vault.config.json`. Rules in `wiki/global/` apply in every project. A **research domain** has `projects: []` and holds pages only, which you read from this folder. `tools/propose.mjs` refuses a rule in it, since no project session would get it, and lint reports one written any other way as an error, which blocks commits.
- `active.md`, `index.md` and `decisions.md`: generated by `node tools/build.mjs`, which each session start and each pick also run. `index.md` lists every page and rule by topic, pages first, each page with its summary. `decisions.md` lists the picks and comments by domain, project and subject, newest first, with their sheets.
- `log.md`: the notes `tools/propose.mjs` wrote or added evidence to and the pages `tools/log.mjs` logged, newest last. Older entries record confirmations, retirements, drops and review decisions from before rules went live on writing.
- `.state/`: the hooks' bookkeeping, including which rules each session was shown.
- `tools/`: the hooks and scripts. Read `tools/CODING_STANDARDS.md` before changing them.

## How rules reach the agent

A note `tools/propose.mjs` writes applies at once. A note saved any other way applies once it has gone `delivery.settleSeconds` (60 by default, in `vault.config.json`) without another save, so a rule being typed in Obsidian doesn't reach sessions half-written. The hooks read each note as it is now:

- `always: true` rules load at the start of every session in the domain's projects, and a session already running gets one with its next prompt.
- Rules with `applies_to` refuse the first matching edit to each file in a session and show the rule. The retry goes through.
- Rules with `keywords` are shown when a prompt mentions one of them.

Each session gets a rule once, and again after its Do, Not or Because changes, or a knowledge rule's `as_of`. A note with a lint error, or with `superseded_by`, is never delivered; `index.md` marks the first kind `not delivered` with its error.

Pages aren't delivered. Every session start names the topics of global and the session's domains (the listed ones, then the others rules and pages have) and points to `index.md`, so the agent reads the pages on a topic its task touches. A session in this folder hears every domain's topics.

A new or resumed session also hears, in one line each, how many errors were logged in `.state/errors.log` since `/lint` last ran, and when `/lint` last ran once it has gone `lint.remindAfterDays` (14 by default, in `vault.config.json`) without a run. Both lines repeat until `/lint` runs.

## Rule notes

```markdown
---
type: rule
domain: roblox-ui
kind: taste
basis: stated
topic: code
always: false
applies_to:
  - 'src/client/UI/**/*.luau'
triggers: []
keywords:
  - strict
created: 2026-10-19
updated: 2026-10-19
---

**Do:** Start every UI script with `--!strict`.
**Not:** Leave scripts in nonstrict mode.
**Because:** Type errors should show up while editing, not in play tests.

## Examples

## Evidence
- 2026-10-19 · stated · session 1a2b3c4d · "I want the agent to always write scripts in !strict" (a-1a2b3c4d)
```

- `kind`: `taste` (the default) or `knowledge`, a fact about an API, version or tool that training gets wrong or doesn't know. Knowledge rules reach the agent only on matching edits, so they need `applies_to` and take no `keywords` or `always`.
- `basis`: `stated` when the user said it, `inferred` when you generalized it from their corrections, `pick` when a recorded answer from an earlier session backs it (a `q-` row in `raw/picks/`, or an older `c-`/`p-` row in `raw/inbox/` that holds the user's own words), `reading` when your own reading of what you saw backs it. Knowledge rules use `stated`, `failure` (something worked only after a failure) or `source` (a dated source shows it).
- `as_of`: knowledge rules only, the day the fact was last checked, as YYYY-MM-DD: the source's date, or the day it was proposed. Delivery shows it, and lint warns once it is more than 180 days old (`knowledge.staleAfterDays` in `vault.config.json`). Taste rules never expire.
- `topic`: a short topic, ideally one the domain's other rules have or `vault.config.json` lists for it. Lint warns on a rule with no topic unless it's superseded. Among delivered rules, it also warns on a topic only one rule in its domain has that the config doesn't list. Global topics aren't checked against the config. `/lint` reports the listed topics no rule has yet.
- `always`: only for short rules that matter in nearly every session. The user sets it in Obsidian; `tools/propose.mjs` refuses it.
- `applies_to`: globs relative to the project root. `**` crosses folders, `*` doesn't, `{a,b}` picks one. Matching ignores case and worktree folders.
- `triggers`: optional regexes tested against the new text of an edit. When present, the rule applies only if one matches.
- `keywords`: optional words or phrases that bring the rule up from a prompt.
- `superseded_by`: optional, the note that replaces this one, as a link or a key like `roblox-ui/new-slug`. The old note stays in the vault and the index, and the hooks stop delivering it. Deleting a note retires its rule too.
- Single-quote globs and regexes so Obsidian reads them as text.
- `**Do:**` and `**Not:**` are required, one line each. Pair every "never X" with an "instead Y". `**Because:**` gives the user's reason; leave it empty rather than invent one. Keep the three lines under 300 characters together, counting the "As of" date a knowledge rule is delivered with.
- `## Evidence` has one line per source: date, kind (`stated` or `correction`; `choice` for a pick), the first 8 characters of the session id, the user's exact words, and the proposal id. A `choice` line also names the options the user passed over and the question, and ends with the pick's id and the proposal id. A `failure` line gives the file, the error as a tool printed it and `fixed by:` the fix; a `source` line gives the URL or `raw/refs/` file, `dated` its date, and its exact words. An `agent's reading` line gives your reading in your own words, unquoted.
- Link notes with `[[wiki/<domain>/<slug>|<slug>]]`.

## Pages

Pages hold knowledge in the agent's words; What belongs here says what counts. The hooks never deliver them; sessions find them through `index.md`. Each page has one `kind`:

- **source** (`source-<slug>.md`): one source, what it says, and the user's words about it. `/ingest` writes it.
- **topic**: sums up what the vault knows on one topic: how its rules and pages fit together, the sources behind them, and what's still open. Each topic in a domain has at most one; `/ingest`, `/lint` and a filed-back answer update it, and start it when the topic has none. Name it after its topic.
- **concept**: one idea, technique or API, explained.
- **entity**: one named thing, such as a library, tool, service or game.
- **synthesis**: an answer or comparison a session worked out from the vault and filed back, so a later session can reuse it.

Check `index.md` that no note has the slug before you start a page.

```markdown
---
type: page
domain: roblox-ui
kind: source
topic: layout
summary: Shop screens the user liked and what they said about the spacing.
source: raw/refs/shop-screens.png
source_date: 2026-09-30
created: 2026-10-22
updated: 2026-10-22
---

## You said
- 2026-10-22 · session 1a2b3c4d · "the cards breathe, the tabs feel cramped"

## Agent's reading
What the source shows, by topic, in the agent's words.

## Rules
- [[wiki/roblox-ui/roomy-cards|roomy-cards]]
```

- `kind`: required, one of the five above. `index.md` labels each page with it, as `source page`, `topic page` and so on. Lint warns on a page without one.
- `topic`: the topic the page belongs under in `index.md`, like a rule's. Lint warns on a page with none.
- `summary`: one line on what the page holds, shown in `index.md`. Lint warns on a page with none. Single-quote it if it holds ` #`, which YAML reads as a comment.
- `source`: source pages, a URL or a file under `raw/` that exists. Lint warns on a source page with none.
- `source_date`: optional, when the source was published or last updated, as YYYY-MM-DD.
- `updated`: the day the page last changed. Set it whenever you change a page. Lint warns on a page other than a source page when a rule it links under `## Rules` changed after it, going by `updated` or, since Obsidian doesn't change `updated`, the day the file was last saved.
- `## You said`: source pages, the user's exact words about the source, one line each with the date and the first 8 characters of the session id. Empty when they said nothing.
- `## Agent's reading`: source pages, the agent's description. It backs a rule only as `basis: reading`, so the rule's note labels it as the agent's.
- `## Rules`: the rules the page draws on. A source page's rules link back under their `## Examples`. A topic page may have none yet, which says no taste is captured on its topic.
- The other pages' bodies are free: write what a session working on the topic should know.
- Cite each claim a source backs with a footnote that names the source: a file under `raw/` or a URL, then its date when it has one. A source page's own source needs none.

  ```markdown
  The tab bar packs six tabs into the top strip.[^1] A UIListLayout spaces them with its Padding.[^2]

  [^1]: raw/refs/shop-screens.png · dated 2026-09-30
  [^2]: https://create.roblox.com/docs/reference/engine/classes/UIListLayout
  ```

- After writing or changing a page, run `node tools/log.mjs wiki/<domain>/<slug>.md` from the vault folder, or from anywhere with both paths in full. It adds a line to `log.md` and rebuilds `index.md`.
- Lint warns on a `[[link]]` that no note or other markdown file in the vault answers, or a bare `[[slug]]` more than one note has, outside code and the user's quoted words. It also warns on two topic pages on one topic in a domain.

## Picks

A pick is the user's choice between options the agent showed them for one piece of work in a domain's project, such as a screen's layout. It holds for that piece; a rule comes from it only when it says something for every piece, through `basis: pick`. `tools/pick.mjs` writes the rows; `node tools/pick.mjs --help` lists the fields.

```json
{"id":"q-1a2b3c4d","at":"2026-10-21T10:00:00.000Z","source":"pick","session":"…","transcript":"…","cwd":"…","domain":"roblox-ui",
 "project":"C:/Users/Lowle/OneDrive/Desktop/roblox-ui","subject":"shop","question":"Which shop layout?","header":null,
 "options":[{"label":"A, Grid","description":"…"},{"label":"B, Featured shelf","description":"…"}],"multiSelect":false,
 "pick":"B, Featured shelf","notes":"the featured rod reads first on phone","reason":null,"status":"user","sheet":"raw/picks/2026-10-21-shop.png"}
```

- `project`: the domain project folder from `vault.config.json` the session ran in. `subject`: the piece of work, lowercase-kebab-case.
- `status`: `user` when the user picked, `provisional` when the agent picked alone while they were away. `notes` is the user's words verbatim, so a provisional pick has none; `reason` is the agent's own.
- `replaces`: the id of the pick this one reverses. A provisional pick can replace only another provisional pick. `confirms`: the id of the provisional pick the user agreed with; the row repeats its question, options, pick and sheet, and its reason unless it gives one. Either one ends the earlier row's turn: a row is live until a later row names it, and only a live row can be named.
- A comment row has `subject` and `text`, the user's words about the piece, and no options.
- `node tools/pick.mjs show <session-id> <subject>` prints the subject's live picks and comments, newest first, then the domain's delivered taste rules, leaving out the topics in the domain's `showSkipTopics` in `vault.config.json`. The rules it prints count as shown to the session. The builder runs it before building or reviewing the piece and pastes its output into the reviewer's prompt.
- A sheet is copied into `raw/picks/`, refused over `picks.maxSheetBytes` (3 MB by default, in `vault.config.json`).
- A provisional, replaced or confirmed pick backs no rule; propose from the live row instead.
- `review.mjs status` lists provisional picks not yet confirmed. Lint warns on a `replaces` or `confirms` that names no row, and on a sheet that doesn't exist.

## What belongs here

- **Rules** are one-line Do/Not taste, and facts training gets wrong, that the hooks deliver. Propose a rule only for what the project's CLAUDE.md or `.claude/rules/` doesn't already say.
- **Pages** are knowledge: concepts, APIs, comparisons, what sources say, and research on any topic, including the background a rule's one line leaves out.
- **Procedures and how-tos**, steps an agent follows, belong in skills; a page may link one. **Project facts**, such as how one project is built or where its files live, belong in that project's CLAUDE.md, docs or auto memory.

## Operations

- **Propose**: in domain sessions the start hook tells you how to propose a rule with `tools/propose.mjs` when the user corrects you, or when a failure or a dated source shows a fact your training gets wrong. In this folder, a session proposes for any domain, as `/ingest` does. `node tools/propose.mjs --help` lists the fields. It writes the note, which applies from then on, and you end your reply with the lines it prints, so the user sees the rule and can edit or delete it. When the rule may repeat ones in the vault, or its words already back another note, it lists them, each marked shown or not shown in this session since its last compaction, and refuses once: propose again with `repeats` set to the rule it repeats, and propose.mjs adds its Evidence line to that note, or propose again as it is if it says something new. Once it writes the note, it names the rules on the same topic whose `applies_to` covers files the new rule's does, so you check the two don't contradict.
- **Re-propose a recorded answer**: a pick or an older captured message that was never turned into a rule can back one from any later session: `basis: pick` with the row's id in `pick`. The row's words are the evidence, so nothing has to be typed again. A row backs one note; proposing it again is refused.
- **Record a pick**: in domain sessions the start hook tells you how to record each pick and comment with `tools/pick.mjs`, and to run its `show` before building or reviewing a piece that has picks.
- **Ingest**: the user runs `/ingest` in this folder with a source: a file under `raw/refs/`, or a URL. You go through it together; it becomes a source page, what they say about it becomes rules, and every topic it touches gets its topic page updated.
- **Query**: when asked what the user prefers or what the vault knows, or when a task touches a topic the session start names, read `index.md`, then the pages and notes on the topic. Every rule there is the user's taste; a rule with `basis: inferred` is your generalization of their corrections, and one with `basis: reading` is your reading of what they showed you, so say so when you lean on either.
- **File back**: when an answer drawn from the vault would help a later session, from any session, add it to the page it extends, or file it as a synthesis page and link that from the topic's page, then log each page you changed with `tools/log.mjs`.
- **Lint**: the user runs `/lint` in this folder for a check of the whole wiki: lint findings, hook errors, rules corrected again in later sessions, rules no session was shown, contradictions, repeats, listed topics no rule has yet, and stale pages. Its first step, `node tools/review.mjs status`, records the run, which quiets the session-start error line and reminder. `node tools/lint.mjs` on its own checks the notes and the generated files; the pre-commit hook rebuilds the generated files and runs it, runs the tests in `test/` when the commit changes `tools/`, `test/` or `.githooks/`, and refuses a commit that rewrites, renames or removes a file in `raw/` unless `VAULT_ALLOW_RAW_CHANGES=1` is set.

## Evidence

- A stated preference or a correction from one session is enough for a rule.
- Cite what backs each rule as it is: the user's words, the error a tool printed and its fix, a dated source and its words, or your own reading. Quote the user's or the source's exact words, marking words left out with …, and give anything else as your reading: `tools/propose.mjs` refuses a quote the user never typed in this session, or one a text file under `raw/refs/` doesn't hold.
- When evidence conflicts, show the user both sides and let them decide.
- The user's own taste beats general best practice. Write rules they expressed, ones a failure or a dated source backs, or your reading of what they showed you, labelled as yours.

## Never

- Change a file that already exists in `raw/`. Put new material in a new file under `raw/refs/`.
- Change the user's words: the quotes under `## Evidence` and `## You said`. Add a line instead.
- Write outside the vault.

The hooks refuse the first, and edits to `active.md`, `index.md`, `decisions.md` and `.state/`. They guard against mistakes, not deliberate workarounds.
